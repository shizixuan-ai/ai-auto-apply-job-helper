# PRD: AI 自动投递助手（BOSS 直聘）

## Problem Statement

求职者在 BOSS 直聘上进行批量岗位投递时，需要逐一阅读岗位描述、手动编写打招呼话术、跟踪投递记录，过程重复且耗时。虽然 BOSS 直聘的"一键投递"简化了操作，但缺少个性化话术生成和投递数据分析能力，导致沟通转化率低，投递状态难以追踪。

## Solution

一个 CLI 工具 `bapply`，通过浏览器自动化（Playwright）与 BOSS 直聘交互，提供：

1. **岗位搜索与抓取** — 按条件搜索岗位，结构化存入飞书多维表格
2. **智能话术生成** — 结合用户简历与岗位 JD，通过 LLM 自动生成个性化打招呼话术，按岗位关联保存
3. **半自动投递** — 用户审核话术后，工具自动执行打招呼操作，用户可在 BOSS 端继续对话
4. **投递分析** — 以飞书多维表格作为数据中心，方便求职者多维度分析和跟踪投递状态

## User Stories

1. 作为一名求职者，我希望通过命令行快速搜索 BOSS 直聘上的岗位，以便将批量岗位纳入我的投递池
2. 作为一名求职者，我希望将搜索到的岗位信息自动同步到飞书多维表格，以便集中管理和分析
3. 作为一名求职者，我希望在多维表格中浏览和筛选岗位，以便标记感兴趣的职位进行下一步操作
4. 作为一名求职者，我希望根据我的简历和目标岗位的 JD 自动生成个性化打招呼话术，以提高 HR 回复率
5. 作为一名求职者，我希望为每个岗位关联专属的话术模板并保存锁定，以便同一岗位再次沟通时使用
6. 作为一名求职者，我希望在审核话术内容后由工具自动执行打招呼操作，以避免手动重复劳动
7. 作为一名求职者，我希望投递结果自动回写到多维表格，以便跟踪各岗位的沟通状态
8. 作为一名求职者，我希望切换不同的 LLM 供应商（DeepSeek / Claude / OpenAI / Ollama 本地模型），以便根据成本和质量偏好选择
9. 作为一名求职者，我希望查看投递统计数据，以便评估求职进展和优化策略
10. 作为一名求职者，我希望登录态持久化保存，以便多次使用无需重复扫码登录
11. 作为一名求职者，我希望通过一个配置文件管理我的简历信息和 LLM 密钥，以便避免每次重复输入

## Implementation Decisions

### 产品形态
- **CLI 工具**，命名 `bapply`，使用 Node.js/TypeScript

### 自动化引擎
- **Playwright** 进行浏览器自动化，模拟真实用户操作
- 使用 Playwright stealth 插件降低被检测风险
- 登录方式：首次调用时打开浏览器，用户手动扫码/手机验证码登录，之后持久化 Cookie

### 数据存储
- **飞书多维表格** 作为数据中心，所有岗位信息、话术模板、投递记录均存储在此
- 用户自行创建飞书自建应用获取 API 凭证（`app_id` + `app_secret`），配置到本地 `.env` 文件
- 多维表格包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| 职位 ID | 文本 | BOSS 直聘唯一标识，去重 |
| 公司名称 | 文本 | |
| 岗位名称 | 文本 | |
| 岗位链接 | 文本 | 打开 BOSS 页面的链接 |
| 状态 | 选项（待投递/已投递/已沟通/不合适） | |
| 自定义话术 | 文本 | 为该岗位生成的打招呼内容 |
| 投递时间 | 日期 | |
| 备注 | 文本 | 观察笔记 |

### LLM 话术生成
- 支持多供应商切换，通过配置文件选择：
  - DeepSeek（默认推荐，性价比高，国内直连）
  - Claude API
  - OpenAI
  - Ollama 本地模型
- 话术按 BOSS 直聘职位 ID 精确匹配保存
- 话术锁定策略：用户确认保存后固定，不会因重新生成而覆盖

### CLI 命令设计

| 命令 | 功能 |
|---|---|
| `bapply init` | 初始化配置（飞书 Token、LLM API Key、简历信息） |
| `bapply login` | 打开浏览器，用户手动登录 BOSS 直聘，保存会话 |
| `bapply search <keyword>` | 搜索岗位，抓取结果写入飞书多维表格 |
| `bapply greet [job-id]` | 为指定或所有标记岗位生成话术 |
| `bapply send <job-id>` | 审核话术后执行打招呼投递 |
| `bapply list` | 查看多维表格中的岗位和状态 |
| `bapply sync` | 同步各岗位的投递状态 |
| `bapply stats` | 投递统计概览 |

### 项目结构

```
boss-apply/
├── src/
│   ├── cli/              # CLI 命令定义（commander/yargs）
│   ├── browser/          # Playwright 浏览器自动化层
│   ├── feishu/           # 飞书多维表格 API 客户端
│   ├── llm/              # LLM 适配器（多供应商切换）
│   ├── template/         # 话术模板生成逻辑
│   ├── config/           # 配置管理
│   └── types/            # TypeScript 类型定义
├── .env.example          # 环境变量模板
├── package.json
└── tsconfig.json
```

### 典型工作流
1. `bapply init` — 配置飞书多维表格 Token、LLM API Key、BOSS 简历信息
2. `bapply login` — Playwright 打开浏览器 → 用户扫码登录 BOSS → Cookie 持久化
3. `bapply search <keyword>` — 搜索岗位，抓取结果写入飞书多维表格
4. 用户在飞书多维表格中浏览、筛选、标记感兴趣的岗位
5. `bapply greet <job-id>` — 读取 JD + 简历 → LLM 生成话术 → 写入多维表格
6. `bapply send <job-id>` — Playwright 打开岗位页 → 填入话术 → 点击打招呼 → 状态回写

## Testing Decisions

- 核心原则：测试外部行为，而非实现细节
- 重点测试模块：
  - **LLM 适配器**：Mock API 调用，验证请求格式和响应解析
  - **飞书 API 客户端**：测试请求构建和响应处理
  - **模板生成逻辑**：以已知 JOD + 简历输入验证话术输出结构
  - **配置管理**：读写配置文件的各种边界情况
- 浏览器自动化层（Playwright）通过集成测试覆盖典型流程

## Out of Scope

- BOSS 直聘以外的招聘平台支持（后续扩展）
- 全自动无人值守投递（当前为半自动，需用户审核）
- 移动端（iOS/Android）版本的 BOSS 直聘支持
- 简历自动优化或生成（仅提供话术生成）
- 多用户/团队协作功能
- Web UI 或 GUI 界面

## Further Notes

- 本工具为个人求职辅助设计，使用时需遵守 BOSS 直聘平台的使用条款
- 浏览器自动化的频率和模式应考虑平台风控策略，避免异常行为检测
- 飞书多维表格的字段结构可在后续使用中灵活扩展
- LLM 供应商切换设计为适配器模式，新增供应商只需实现统一接口
